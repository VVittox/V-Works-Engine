# Рендер и производительность

В движке существует **PygameRenderer**, который рисует 2D и обрабатывает программный 3D. Дополнительный `GpuTriangles3D` использует ModernGL/OpenGL 3.3 для растеризации 3D-треугольников.

## CPU / GPU / Auto

Project → Project Settings → Runtime → 3D renderer:

- `cpu`: программная обработка и отрисовка через Pygame.
- `gpu`: попытка использовать ModernGL; при ошибке остаётся CPU.
- `auto`: автоматическое использование доступного GPU-бэкенда.

Для GPU установите `requirements-gpu.txt`. В режиме Game View выберите **Engine runtime Game View**, если хотите смотреть именно на runtime renderer.

## Что действительно ускоряет GPU в этой версии

OpenGL отвечает за клиппинг, перспективную растеризацию и Z-buffer, а часть трансформации геометрии и освещения остаётся на CPU. Результат считывается из OpenGL обратно в Pygame Surface. Это промежуточная архитектура, поэтому рост FPS не гарантирован; readback может стать узким местом.

## Что пока отсутствует

Не заявлены как готовые: полноценный GPU mesh cache с сохранением данных на видеокарте, 3D PBR, универсальные GLSL-материалы, Shadow Maps с полноценным освещением, рендер без readback и мобильный OpenGL ES runtime. Эти возможности требуют отдельной разработки.

## Профайлинг

Откройте View → Profiler, включите диагностические overlays в Project Settings, проверяйте количество мешей, отсечённых объектов и время кадра. Сравнивайте одну и ту же сцену при одинаковом разрешении и числе нод. Для нагрузочных тестов есть `project/scenes/performance_1000.vscene` и `tools/benchmark_many_objects.py`.

## Рекомендации по оптимизации

Используйте простые meshes и разумные размеры текстур, проверяйте collision shapes отдельно от визуальной модели, не делайте тяжёлую обработку каждый `_process`, запускайте профайлер до преждевременной оптимизации. Учитывайте, что встроенный Qt viewport и игровая отрисовка отличаются по устройству.
